视频模仿 DP 管线

部署时 G1 只看自己的头部相机画面和本体状态。DP encoder 先回归未来的 3D 场景流，再以它为条件生成头和双手的未来轨迹 kp̂，最后生成 SuperMimic 的 latent z，交给冻结的 SuperMimic decoder 执行。人 ego 视频和部署任务相同，只当训练数据，部署时不输入示范。训练分三个 stage：mocap 蒸馏、人视频、仿真 RL 后训练，全程不用遥操作。

三条设计约束

3 点是唯一枢纽mocap 有 3 点和 z，没有图像；人视频有图像和 3 点，没有 z。头和双手的 3 点是两份数据唯一的交集，所以模型拆成"ego → 3 点"和"3 点 → z"两段来学，两段之间的耦合交给 RL。
场景流是人机之间的桥视觉通路先回归相机稳定的 3D 场景流（全图，包含手 / 机械臂），DiT 读它的隐状态 h_f。人手和夹爪做出相同的物理动作，得到相近的监督，与外观无关。
RL 只改执行者怎么动stage 3 的 FlashSAC 只引导 kp 的初始噪声，z 由 DP 忠实执行。成功的 rollout 按轮次蒸馏回 DP 的 kp 通路，z 通路保持 mocap 先验。机器人数据只来自这里。

Mask 与噪声配置

"DP encoder"指 flow query 加 masked DiT 的整体。它是一个 uni model：每个 token 的角色由噪声水平 τ 和损失权重决定。

状态输入loss含义
条件干净值，τ = 0无已知，只被读
目标加噪，τ ∈ (0, 1)flow matching要生成
缺失纯噪声，τ = 10既不当条件，也不监督

只当条件、不生成的输入（当前帧、h_f、本体、zₜ₋₁）只有"给 / 空 token"两种状态。生成模态（kp、z）缺数据时用 τ = 1、权重 0，不用空 token：τ = 1 等价于把这个模态边缘化，部署第 ① 步去噪 kp 时 z 也正处在 τ = 1，训练和推理一致。两步采样对应的两种配置（kp 目标 + z 缺失；kp 条件 + z 目标）要显式、高概率地采到。

Stage 1 · mocap 蒸馏

MorphMimic 式蒸馏无图像

先用 BONES-SEED 学会"3 点 → z"，同时学会下半身的补全和 z 的时间一致性。主要配置是 kp 作条件、z 作目标，即 p(z | kp, 本体, zₜ₋₁)，对应 MorphMimic HumanEncoder 的角色；同时以较低概率让 kp 作目标，学一个不看图像的 kp 先验。训练方式照搬 MorphMimic 的 student 蒸馏：teacher（enc_motion + decoder）冻结；仿真里一半环境由 DP 执行，rollout 进 replay buffer；标签在 f_ω 的想象里、用 student 自己访问到的状态当场计算。

配置与输出
主要是 kp 条件 → z 目标；脚的字段几乎总是 mask，手偶尔 mask。一次输出一段 z（长度和每 8 步重规划对齐），以 zₜ₋₁ 为条件。
损失
MorphMimic 的 latent 项换成以 z_motion 为目标的 flow matching；动作 copy 项用单步 x0 估计 ẑ₀ 计算，只加在低噪声的 τ 上，以免压掉多峰性。
上线前检查
只给头 + 双手 3 点时，DP 和 MLP HumanEncoder（同一 teacher、同一 decoder）对比头/手误差、摔倒率、‖Δz‖；接近任务姿态的 clip 单独统计。

Stage 2 · 人视频

必需100 条 ego 视频单条视频

这一步训练视觉通路："当前帧 → 场景流、kp̂"。每个样本只用一条视频：第 t 帧作当前帧，监督同一条视频的未来 3 点和 3D 场景流，和 EgoWAM 的共训设定一样。它是视觉通路唯一的先验来源：没有这一步，DP 在仿真里的初始成功率接近 0，stage 3 的 RL 就没有起点。

Stage 3 · 仿真 RL 后训练

can-pnpFlashSAC + SGS按轮次自模仿

参考实现是仓库里现有的 five-point 流程（experiments/train_fivepoint.py、hskill/learners/flashsac/、hskill/data/sgs.py），把其中冻结的 five-point FM 换成 DP。现有的"five-point FM + MorphMimic HumanEncoder"两段，正好对应 DP 的 kp 分支和 kp → z 分支；去掉示范输入后，actor 的输入结构和现有代码一致。每一轮先让 FlashSAC 在冻结的 DP 上学，再把成功 rollout 蒸馏回 DP。机器人数据只来自这里。

V-JEPA、decoder冻结—
  • kp 标签取下发的 kp̂。成功就是它作为命令带来的，蒸馏的是完整的策略 π_w∘DP。如果 tracker 跟踪误差大，再改用实际 FK 做 hindsight 重标注。
  • z 分支不更新。π_w 不控制 ε_z，rollout 里的 z 只是 DP 自己的采样，只多了"成功"这一层筛选，信号弱；z 分支有 stage 1 的 teacher 兜底。
  • 共享主干。"只更新 kp 分支"在参数上分不干净，靠 z 缺失 + 混入 stage 1 batch + KL 来约束；要隔离得更彻底，可以在 kp 分支上用 LoRA，或只解冻 kp 的进出投影和最后几层。

按轮次交替

π_w 的输出是 DP 的初始噪声，critic 学的是 Q(s, ε)，replay 存的是 (s, ε, r, s′)，三者都依赖 DP 当前的参数。DP 一更新，同一个 ε 生成的 kp̂ 就变了，三者一起失效。所以 DP 只在轮与轮之间更新，这就是"慢更新"。

  1. RL 阶段：DP_k 冻结。FlashSAC 训练 π_w 和 critic，SGS 选起点，成功 rollout 存进成功池；成功率稳定或到固定步数就停。
  2. 蒸馏阶段：π_w 不再更新。用成功池按上表训练 DP，混入 stage 1/2 数据，加 KL 拉向 DP_k，得到 DP_{k+1}。
  3. 重置：π_w 回到初始化（和观测无关、方差与 DP 先验一致的 tanh-Gaussian），critic 重新初始化，replay 清空。SGS 的成功率历史保留，它记录的是起点难度，和 DP 参数关系不大。

重置不会白学：π_w 学到的改进已经蒸馏进 DP_{k+1}，下一轮从更高的先验起步。代价是每轮都要重新热身 critic。替代方案是让 critic 读 kp̂（DSRL-NA 式：先在动作空间学 Q(s, kp̂)，再蒸馏到噪声空间），DP 更新后 critic 和 replay 仍然有效，但要改现有 critic 的输入。第一版用按轮次重置。

相对 v5 去掉的：示范视频输入、video query、进度 φ、f_ω 想象 BPTT、3 点一致性想象奖励、示范池 α 和监督 β 的调度。

场景流标签怎么来

标签定义与 EgoWAM 一致：在当前帧 t 上取 N 个查询点（例如 28×40 网格，覆盖全图，包含手 / 机械臂），记录它们在 t 到 t+T 之间的 3D 位置，全部表示在 t 时刻的相机坐标系里（重力对齐），这样头部相机自身的运动就被扣掉了。静止点按位移阈值过滤（EgoWAM：机器人 2 mm、人 10 mm），剩下的运动点大多落在执行者和被操作的物体上。

构建顺序

  1. 诊断：在 BONES-SEED 上批量算 z* = enc_motion(g)，看每一维的分布、饱和比例和有效维数；给 z* 加不同幅度的噪声跑闭环，测 decoder 对 z 误差的敏感度。结果决定 flow matching 直接在 z 空间做，还是先做 atanh 或标准化。
  2. 执行接口：给 SuperMimic 加一个直接从 z 出发的入口 a = dec(z, o_hist)。
  3. Stage 1：移植 MorphMimic 的 student 蒸馏流程（半数环境由 student 执行，想象里当场算 teacher 标签），先用 MLP HumanEncoder 跑通，再换成 masked DiT（kp tokens 和 z tokens，逐 token 时间步，交叉注意力读条件，空 token 与来源 token）。
  4. 视觉通路：预先算好 V-JEPA 2.1 特征；人视频跑 SLAM、HaMeR、Track4World 得到 3 点和场景流标签；实现 flow query，训练 stage 2。
  5. 重置库：100 条人示范的 3 点经 stage 1 DP → decoder 在仿真里回放，按 phase 取起点。
  6. Stage 3：在 train_fivepoint.py 上把 five-point FM 换成 DP（actor 读 DP 条件 tokens、输出 ε_kp），tracker 换成 DiT 的 z 分支 + SuperMimic decoder；can-pnp 导出场景流真值（包含机器人连杆）；外面套一层轮次循环，加一个成功池蒸馏脚本。

待定问题

  • 场景流能否单独弥合人机差异：EgoWAM 的结论建立在有遥操作数据兜底的前提上，我们的机器人帧要到 stage 3 才出现（仿真渲染）。关键实验是 stage 2 → stage 3 第一轮的迁移：只在人帧上训练的视觉通路，面对机器人渲染帧时 kp̂ 和 h_f 是否还合理。廉价的检验是跨执行者探针：人帧上训练"当前帧 → 未来 3 点"，在 G1 渲染帧上测试，对比加 / 不加场景流辅助回归。备选（已讨论、暂不采用）：输入里 mask 掉执行者，并加一个跨执行者共用的当前 3 点 token。
  • stage 2 没有本体：人视频里模型只能从图像判断"手现在在哪"，部署时本体里有这个信息，但 stage 2 没学过去读它。如果迁移不好，给 stage 2 一个由 SLAM + HaMeR 得到的当前 3 点作为本体的替代。
  • 三重视觉域差：人的真实视频、G1 的仿真渲染、G1 的真实相机。
  • 扣除相机运动：人视频用 SLAM/VIO 的头部位姿，G1 用 FK 的头部位姿。G1 走路时头部相机一直在晃，这一步比 EgoWAM 的固定相机设定重要得多。
  • 先验缺任务姿态：BONES-SEED 过滤掉了带物体接触的 clip，前倾、下蹲够物这类姿态可能很少，噪声空间 RL 可能够不到。按轮次蒸馏只更新 kp 通路；如果瓶颈在 z 分支（任务姿态 → z），需要再放开 z 分支，或改用 RECAP 式的优势条件化直接微调 DP。
  • 按轮次蒸馏的漂移：kp 通路反复吸收 π_w 的改写，可能偏离 stage 2 学到的人视频先验。蒸馏时混入 stage 2 数据并加 KL。
  • 伪标签噪声：HaMeR 在手被遮挡时会抖，直接进入 stage 2 的 kp 标签；做时间平滑、按置信度加权。
  • Stage 3 待确认：f_ω 只留在 stage 1，stage 3 不用；kp 用 3 点还是 5 点（现有 tracker 是 human/five 版，倾向 DP 生成 3 点、脚保持 mask）。
