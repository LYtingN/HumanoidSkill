视频模仿 DP 管线

部署时给 G1 一条人的 ego 示范视频。DP encoder 读这条示范和机器人当前的观测，输出 SuperMimic 的 latent z，交给冻结的 SuperMimic decoder 执行。DP encoder 分两侧：上下文侧用可学习 query 压缩示范、回归未来的 3D 场景流；生成侧是一个 masked DiT，先采样 kp̂，再以 kp̂ 为条件采样 z。训练分三个 stage：mocap 蒸馏、人视频、仿真 RL 后训练。

三条设计约束

3 点是唯一枢纽mocap 有 3 点和 z，没有图像；人视频有图像和 3 点，没有 z。头和双手的 3 点是两份数据唯一的交集，所以模型拆成"ego → 3 点"和"3 点 → z"两段来学，两段之间的耦合交给 RL。
kp̂ 是生成出来的，不是照抄示范示范里物体的位置和机器人眼前的场景不一样，而且改写的方式不止一种。kp̂ 用扩散生成，再作为 z 的条件。
stage 3 第一次凑齐配对数据仿真 rollout 同时有图像、3 点、z、本体状态和精确的场景流。成功的 rollout 既能当机器人示范，也能当配对的监督。

视觉组件

视觉模型有两个角色：输入编码器每个控制周期都要跑，预测目标只在训练时当标签。示范和当前帧用同一个编码器，这样模型可以直接在同一个特征空间里比对"示范进行到哪一步"和"示范里的物体对应眼前哪一个"。

Stage 1 · mocap 蒸馏

MorphMimic 式蒸馏无图像

先用 BONES-SEED 学会"3 点 → z"，同时学会下半身的补全和 z 的时间一致性。训练方式照搬 MorphMimic 的 student 蒸馏：teacher（enc_motion + decoder）冻结；仿真里一半环境由 DP 执行，rollout 进 replay buffer；标签在 f_ω 的想象里、用 student 自己访问到的状态当场计算。z 的标签来自 enc_motion，所以生成的 z 天然落在 decoder 认识的流形上。

掩码与输出
脚的字段几乎总是 mask，手偶尔 mask。一次输出一段 z（长度和每 8 步重规划对齐），以 zₜ₋₁ 为条件。
损失
MorphMimic 的 latent 项换成以 z_motion 为目标的 flow matching；动作 copy 项用单步 x0 估计 ẑ₀ 计算，只加在低噪声的 τ 上，以免压掉多峰性。
上线前检查
只给头 + 双手 3 点时，DP 和 MLP HumanEncoder（同一 teacher、同一 decoder）对比头/手误差、摔倒率、‖Δz‖；接近任务姿态的 clip 单独统计。

Stage 2 · 人视频

可选，推荐最简版100 条 ego 视频

这一步训练视觉通路："示范视频 + 当前帧 → kp̂、场景流"。从同一任务里取两条不同实例的视频，A 当示范，B 当"当前"，模型学着把 A 的 3 点改写成符合 B 场景的 3 点。跳过这一步也能跑（直接用示范 3 点当目标），但 stage 3 的 RL 就要从零学会"根据场景改写示范"。

Stage 3 · 仿真 RL 后训练

can-pnp人 / 机器人视频混合

闭环跑在 can-pnp 仿真里，当前观测始终是 G1 相机的渲染。示范从示范池里采样：池里一开始只有人视频，成功的机器人 rollout 会被渲染成视频加进来。RL 只训练一个噪声空间的策略 π_w（DSRL），这样 z 始终经过 DP 的去噪器生成。f_ω 的用法和 SuperMimic 训练自己的策略时一样，只用来辅助训练：仿真 rollout 写进 replay buffer，f_ω 在 buffer 上交替重拟合；π_w 从 buffer 里的状态出发，在冻结的 f_ω 里想象 H 步，通过 BPTT 拿到一阶梯度。抓取和放置这类不连续的结果 f_ω 推不出来，靠仿真奖励。

场景流标签怎么来

标签定义：在当前帧 t 上取 N 个查询点，记录它们在 t 到 t+T 之间的 3D 位置，全部表示在 t 时刻的相机坐标系里（重力对齐）。这样头部相机自身的运动就被扣掉了。执行者自己身上的点 mask 掉，那部分由 kp 负责。

人视频和机器人视频怎么混

需要混合的地方有两处，节奏不一样。示范来源的比例 α 要设上限：部署时给的示范永远是人视频，如果 α 升到 1，模型就忘了怎么读人视频。监督 batch 里机器人数据的比例 β 可以升得更高，因为它监督的是机器人自己的观测。

  • 示范 → 当前这对组合也在变：早期全是"人示范 → 机器人执行"，这正是部署时的组合；"机器人示范 → 机器人执行"更容易，适合用来稳定训练，但不能占多数。
  • 3 点一致性奖励要放宽：示范场景和仿真场景里物体位置不同，奖励应该约束手相对物体的位姿和阶段进度 φ，不能逐帧约束绝对位置。

构建顺序

  1. 诊断：在 BONES-SEED 上批量算 z* = enc_motion(g)，看每一维的分布、饱和比例和有效维数；给 z* 加不同幅度的噪声跑闭环，测 decoder 对 z 误差的敏感度。结果决定 flow matching 直接在 z 空间做，还是先做 atanh 或标准化。
  2. 执行接口：给 SuperMimic 加一个直接从 z 出发的入口 a = dec(z, o_hist)。
  3. Stage 1：移植 MorphMimic 的 student 蒸馏流程（半数环境由 student 执行，想象里当场算 teacher 标签），先用 MLP HumanEncoder 跑通，再换成 masked DiT（kp tokens 和 z tokens，逐 token 时间步，交叉注意力读条件，空 token 与来源 token）。
  4. 视觉通路：预先算好 V-JEPA 2.1 特征；人视频跑 SLAM、HaMeR、Track4World 得到 3 点和场景流标签；实现 video query 和 flow query，训练 stage 2。
  5. Stage 3：can-pnp 里渲染 G1 相机、导出场景流真值；照 SuperMimic 的循环搭 replay buffer → f_ω 重拟合 → 想象 BPTT 更新 π_w，想象 rollout 里的动作换成 dec(z, o_hist)；再接入仿真任务奖励；示范池和 α、β 调度。

待定问题

  • 示范与执行的时间对齐：机器人比人慢，kp tokens 里的进度 φ 决定读示范的哪一段。φ 在 stage 1 有真值（clip 的时间索引），在 stage 2 有近似真值（A、B 按任务阶段对齐），在 stage 3 只能靠奖励间接约束。
  • 三重视觉域差：人的真实视频、G1 的仿真渲染、G1 的真实相机。场景流目标与外观无关；输入端靠冻结的 V-JEPA 2.1，必要时再把手 mask 掉。
  • 扣除相机运动：人视频用 SLAM/VIO 的头部位姿，G1 用 FK 的头部位姿。G1 走路时头部相机一直在晃，这一步比 EgoWAM 的固定相机设定重要得多。
  • 先验缺任务姿态：BONES-SEED 过滤掉了带物体接触的 clip，前倾、下蹲够物这类姿态可能很少，DSRL 在噪声空间里可能够不到。出现这种情况时，改用 RECAP 式的优势条件化直接微调 DP。
  • f_ω 看不到物体：在 can-pnp 的 rollout 上重拟合后能学到一部分负载效应，但状态里没有物体和夹爪，抓起罐子前后的动力学变化对它来说只是部分可观测。想象奖励只用在身体和手的平滑部分。
  • 伪标签噪声：HaMeR 在手被遮挡时会抖。stage 1 对示范 3 点加的扰动，幅度要和实测的伪标签误差匹配。
